## 一、專案概述

### 1.1 專案背景

肺癌為台灣男性第二大、女性第一大癌症死因。化學治療是肺癌主要治療方式之一，然而第一次化療往往是病人最焦慮、最需要資訊支持的階段。研究顯示，化療後症狀困擾（如噁心、嘔吐、疼痛、疲勞）與心理困擾（如焦慮、憂鬱、無望感）顯著影響生活品質。

目前臨床衛教多以制式單張提供，缺乏個別化、即時性的回應。本專案擬運用檢索增強生成（Retrieval-Augmented Generation, RAG）技術，建立一套基於實證文獻的智慧衛教聊天機器人。

### 1.2 專案目標

- **主要目標**：開發基於 RAG 的衛教聊天機器人，提供肺癌化療後症狀與心理變化的實證衛教
- **次要目標 1**：建立結構化實證知識庫，涵蓋化療後生理症狀、心理反應、自我照護策略
- **次要目標 2**：確保所有回答可追溯至原始文獻，滿足醫療資訊安全要求
- **次要目標 3**：支援中文（繁體）自然語言互動，降低患者使用門檻

### 1.3 範圍界定

| 內容領域 | 納入範圍 | 排除範圍 |
|---|---|---|
| 症狀管理 | 化療後常見症狀（噁心嘔吐、疲勞、疼痛、口腔黏膜炎、周邊神經病變、食慾不振、排便變化、睡眠障礙） | 診斷、處方、緊急醫療處置 |
| 心理支持 | 焦慮、憂鬱、恐懼、身體形象變化、因應策略 | 心理治療、精神科處方 |
| 自我照護 | 飲食、運動、休息、感染預防、日常生活調適 | 替代療法推薦 |
| 資訊提供 | 化療流程說明、何時就醫指引 | 特定藥物副作用查詢 |

### 1.4 理論框架

- **症狀管理理論 (SMT)**：Dodd et al. (2001) 提出症狀經驗、症狀管理策略與症狀結果三大構面，作為衛教內容組織框架
- **壓力與因應理論 (Lazarus & Folkman, 1984)**：化療後心理調適過程的理論基礎
- **自我效能理論 (Bandura, 1977)**：透過資訊提供增強患者自我照護信心

## 二、文獻基礎與實證依據

### 2.1 文獻類型與證據等級

| 文獻類型 | 內容範圍 | 證據等級 | 來源舉例 |
|---|---|---|---|
| 系統性文獻回顧 | 化療後症狀盤點與介入效果 | Level I | Cochrane Library, JBI |
| 臨床指引 (CPG) | 症狀處理流程與建議 | Level I | NCCN, ONS PEP, ESMO |
| 隨機對照試驗 (RCT) | 特定症狀介入效果 | Level II | Oncology Nursing Forum |
| 世代研究 / 橫斷研究 | 症狀盛行率與影響因子 | Level III-IV | Supportive Care in Cancer |
| 質性研究 | 患者主觀經驗與心理感受 | Level V | Qualitative Health Research |
| 專家共識 / 教科書 | 基礎病理生理學解釋 | Level VI-VII | Harrison's, Brunner & Suddarth's |

### 2.2 化療後常見症狀概述

| 症狀分類 | 常見症狀 | 好發時間（化療後） | 盛行率 |
|---|---|---|---|
| 消化道症狀 | 噁心、嘔吐 | 24–72 小時 | 60–80% |
| 消化道症狀 | 食慾不振 | 第 1–2 週 | 40–70% |
| 消化道症狀 | 便秘 / 腹瀉 | 第 1–2 週 | 30–50% |
| 全身性症狀 | 疲勞 (Cancer-related Fatigue) | 第 1–3 週 | 70–100% |
| 全身性症狀 | 疼痛 | 第 1 週起 | 30–50% |
| 血液系統 | 骨髓抑制（白血球下降） | 第 7–14 天 (Nadir) | 60–80% |
| 口腔症狀 | 口腔黏膜炎 | 第 5–14 天 | 20–40% |
| 神經系統 | 周邊神經病變 | 第 2–3 週起 | 20–30% |
| 外觀變化 | 脫髮 | 第 2–3 週 | 50–80% |
| 睡眠障礙 | 失眠 / 嗜睡 | 第 1 週起 | 30–60% |

> [!tip] 這張表與現行知識庫的對照
> 上表的症狀幾乎都對應到現有的 ONC 單張：[[ONC-21 噁心嘔吐食慾不振]]、[[ONC-23 便祕]]、[[ONC-22 腹瀉]]、
> [[ONC-37 疲憊]]、[[ONC-25 白血球低下]]、[[ONC-17 口腔黏膜炎]]、[[ONC-38 周邊神經病變]]、[[ONC-24 毛髮脫落]]。
> 缺的是**疼痛**與**睡眠障礙**兩份 —— 現行知識庫沒有涵蓋，但盛行率分別是 30–50% 與 30–60%。

### 2.3 化療後心理狀態變化

- **焦慮**：盛行率約 30–50%，尤其對化療副作用的不確定感、對預後的擔憂
- **憂鬱**：盛行率約 20–40%，與功能狀態下降、社會支持不足相關
- **身體形象困擾**：脫髮、體重變化導致自尊下降
- **不確定感**：對治療效果、疾病進展的不確定感是主要心理壓力源
- **因應機制**：情緒導向 vs. 問題導向因應，資訊尋求行為差異大

### 2.4 文獻搜尋策略

| 項目 | 內容 |
|---|---|
| 資料庫 | PubMed, CINAHL, Cochrane Library, 華藝線上圖書館 |
| 搜尋年限 | 2015–2026 |
| 關鍵字 | `lung cancer AND chemotherapy AND (symptom* OR psychological OR anxiety OR depression OR self-care OR patient education)` |
| 納入標準 | 英文/中文全文、成人肺癌患者、化療相關 |
| 排除標準 | 兒童肺癌、單純基因治療、非衛教介入 |

## 三、RAG 系統架構設計

### 3.1 系統架構總覽（四層式）

| 層次 | 元件 | 技術選型 | 說明 |
|---|---|---|---|
| Layer 1 知識庫建構 | PDF Parser + Chunker | PyMuPDF + 自定義 Splitter | 實證文獻解析與分層切割 |
| Layer 1 | Embedding Model | nomic-embed-text (Ollama) | 本地向量化，支援中英雙語 |
| Layer 1 | Vector Store | ChromaDB | 雙集合儲存（症狀 + 心理） |
| Layer 2 檢索引擎 | Query Preprocessor | 中英轉換 + 醫學縮寫擴展 | 理解患者口語化提問 |
| Layer 2 | Hybrid Search | 語意搜尋 + BM25 關鍵字 | 提高召回率 |
| Layer 2 | Reranker | Cross-encoder (ms-marco) | 精確排序檢索結果 |
| Layer 3 生成引擎 | LLM | Gemini Flash / Claude Sonnet | 結構化衛教回答生成 |
| Layer 3 | Safety Guard | 自定義規則引擎 | 醫療安全護欄 |
| Layer 4 使用者介面 | Frontend | React + LINE Bot | 多通道互動介面 |
| Layer 4 | API Server | FastAPI (SSE Streaming) | 即時串流回應 |

### 3.2 知識庫設計

#### 3.2.1 分層 Chunking 策略

| 層級 | 粒度 | 內容舉例 | 用途 |
|---|---|---|---|
| L1 主題層 | 疾病/主題 | 肺癌化療後噁心嘔吐 | 導航與分類 |
| L2 章節層 | 衛教面向 | 症狀說明 / 自我照護 / 何時就醫 | 主要檢索單位 |
| L3 段落層 | 具體建議 | 生薑飲食建議、嘔吐時姿勢調整 | 精確配對 |

#### 3.2.2 Metadata 設計

| 欄位 | 型別 | 說明 | 範例 |
|---|---|---|---|
| `source_type` | string | 文獻證據等級 | CPG / RCT / SR / Expert |
| `symptom_category` | string | 症狀分類 | GI / fatigue / pain / neuro |
| `domain` | string | 衛教領域 | symptom / psychology / self-care |
| `timeline` | string | 症狀時序 | acute / subacute / chronic |
| `evidence_level` | string | 證據等級 | I / II / III / IV / V |
| `citation` | string | 參考文獻 | Author (Year). Title. Journal |
| `last_updated` | date | 最後更新日期 | 2026-03-31 |

#### 3.2.3 雙集合設計

- `symptom_collection`：生理症狀相關衛教內容（症狀說明、處理方法、就醫指引）
- `psychology_collection`：心理狀態相關衛教內容（情緒調適、因應策略、社會支持）

檢索時根據問題意圖自動路由至對應集合，或同時查詢兩個集合後合併結果。

### 3.3 檢索引擎設計

#### 3.3.1 查詢前處理

- **口語轉換**：「化療後一直想吐」→「化學治療後噁心嘔吐症狀」
- **繁簡轉換**：支援簡體中文輸入自動轉換
- **醫學同義詞擴展**：「想吐」→「噁心」「嘔心 ❓」「嘔吐」
- **意圖分類**：判斷為症狀查詢 / 心理支持 / 自我照護 / 緊急識別

#### 3.3.2 檢索策略（Hybrid Search + Cross-encoder Rerank）

| 階段 | 方法 | 說明 |
|---|---|---|
| 第一階段：召回 | 語意搜尋 (top-20) + BM25 (top-20) | 合併後取聯集，確保廣度 |
| 第二階段：重排 | Cross-encoder Rerank (top-5) | 以 query-document pair 精確評分 |
| 後處理 | 證據等級加權 | 優先回傳高證據等級內容 |

### 3.4 生成引擎設計

#### 3.4.1 Prompt 模板設計

- **角色定義**：你是一位專業的腫瘤護理衛教師，專門協助肺癌化療患者
- **回答原則**：僅基於檢索到的文獻回答，不提供診斷或處方
- **輸出格式**：結構化回答（症狀說明 → 自我照護建議 → 何時就醫 → 參考文獻）
- **安全護欄**：識別緊急情況時立即引導就醫
- **語調**：溫暖、同理、避免醫學專業術語、適應患者理解程度

#### 3.4.2 安全護欄機制

| 識別情境 | 觸發條件 | 系統回應 |
|---|---|---|
| 緊急症狀 | 咳血、呼吸困難、高燒 >38.5°C、劇烈胸痛 | 立即引導急診 / 撥急診電話 |
| 診斷詢問 ❓ | 「我這是不是復發了」「我的指數正常嗎」 | 建議詢問主治醫師，不提供判斷 |
| 心理危機 | 自殺/自傷意念、極度絕望 | 提供安心專線、建議立即求助 |
| 處方查詢 | 「可以吃XX藥嗎」「藥量調整」 | 明確告知無法提供藥物建議 |
| 無相關內容 | 與肺癌化療無關的問題 | 引導回衛教範圍或建議其他資源 |

> [!tip] 這張表比現行版本好
> 現行 [[v1.0 系統架構書]] 的 4.3 只有扁平的關鍵字清單，
> 而這裡是「情境 → 觸發條件 → 明確回應」的對應，且：
> - 給了**具體閾值**（高燒 >38.5°C），現行版只寫「發高燒」
> - 心理危機給的是**安心專線**這種可行動的轉介，現行版只寫「請按呼叫鈴」
>
> 若要修 [[Review 問題清單#2. 緊急警示會延遲 25–35 秒才通知護理師]]，
> 這張表可以直接拿來當短路回覆的內容來源。

## 四、衛教內容架構

### 4.1 依 SMT 三構面組織

| SMT 構面 | 衛教模組 | 內容舉例 |
|---|---|---|
| 症狀經驗 | 症狀說明 | 噁心是什麼？為什麼化療後會噁心？ |
| 症狀經驗 | 症狀時序 | 什麼時候開始？持續多久？什麼時候會好轉？ |
| 症狀管理策略 | 自我照護指引 | 非藥物處理方法、飲食調整、活動建議 |
| 症狀管理策略 | 何時就醫 | 警示症狀識別、就醫指引 |
| 症狀結果 | 預期管理 | 化療後復原時程、下次化療前準備 |

### 4.2 心理支持內容設計

| 心理主題 | 衛教內容 | 理論依據 |
|---|---|---|
| 化療前焦慮 | 化療流程說明、常見副作用預告、不確定感因應 | Mishel Uncertainty Theory |
| 化療中痛苦 | 痛苦正常化、情緒調節技巧、放鬆引導 | Lazarus & Folkman 因應理論 |
| 身體形象 | 脫髮正常化、外觀調適建議 | Self-concept Theory |
| 社會支持 | 家屬溝通指引、病友支持團體資訊 | Social Support Theory |
| 自我效能 | 成功經驗分享、漸進式目標設定 | Bandura Self-efficacy |

> [!warning] 現行知識庫完全沒有心理支持內容
> 13 份 ONC 單張全部是生理症狀。唯一沾到邊的是 [[ONC-24 毛髮脫落]] 提及
> 「47% 的女性病人認為化療引起的落髮嚴重影響生活品質」，但沒有調適策略。
> 本草案的雙集合設計（症狀 / 心理）因此在現行資料下無從實現。

### 4.3 對話情境範例

> [!example] 患者提問
> 「我化療完第二天一直想吐，吃不下東西，怎麼辦？」

> [!success] 機器人回應範例
> 化療後感到噁心和食慾不振是很常見的情況，通常在化療後 24-72 小時最明顯。以下是一些可以幫助您的方法：
>
> ❖ **症狀說明**：化療藥物會影響消化道黏膜，引起噁心感。通常第 2-3 天最明顯，之後會逐漸緩解。
>
> ❖ **自我照護建議**：少量多餐（每 2-3 小時少量進食）、避免油膩、可嘗試蘇打餅乾緩解噁心、適度休息但避免飯後立即平躺。
>
> ❖ **何時就醫**：若持續嘔吐超過 24 小時無法進食、出現脫水症狀（尿量減少、頭暈），請立即聯繫您的醫療團隊。
>
> 參考來源：NCCN Antiemesis Guidelines (2025); ONS PEP: Chemotherapy-Induced Nausea
>
> 免責聲明：本資訊僅供參考，不構成醫療建議。若有任何疑慮，請諮詢您的主治醫師。

## 六、評估計畫

### 6.1 系統效能評估

| 評估面向 | 指標 | 評估方法 | 目標值 |
|---|---|---|---|
| 檢索品質 | Precision@5, Recall@10 | 專家標註測試集（50 題） | ≥ 0.80 |
| 回答正確性 | 專家評分（1–5 分） | 腫瘤護理專家盲審 | ≥ 4.0/5.0 |
| 安全性 | 不當建議率 | 紅隊測試（100 題攻擊性提問） | 0% |
| 來源可追溯性 | 有引用率 | 自動檢測回答是否含引用 | ≥ 95% |
| 回應時間 | 首字元延遲 (TTFB) | 自動化監控 | ≤ 3 秒 |
| 用戶滿意度 | SUS 可用性量表 | 試用者問卷 | ≥ 70/100 |

> [!failure] 現行 v1.0 的回應時間是 25–35 秒，比這個目標差一個數量級
> 這份草案訂 TTFB ≤ 3 秒（靠 SSE 串流），現行版沒有串流，Gemma 3 12B 要跑完 800 tokens 才回。

### 6.2 內容品質審查流程（三階段）

1. **自動檢測**：引用檢查、安全護欄觸發率、回答結構完整性
2. **專家審查**：腫瘤護理師定期抽查對話紀錄，評估內容正確性與適切性
3. **用戶回饋**：每次對話後的滿意度評分與意見回饋

## 七、倫理與法規考量

### 7.1 醫療 AI 倫理原則

| 原則 | 實踐方式 |
|---|---|
| 行善 (Beneficence) | 提供實證基礎衛教，協助症狀自我管理 |
| 不傷害 (Non-maleficence) | 安全護欄防止不當建議，緊急情況即時引導就醫 |
| 自主 (Autonomy) | 明確告知是 AI 系統，保留患者決策權 |
| 公義 (Justice) | 免費使用、多通道接入、考慮數位落差 |
| 透明 (Transparency) | 回答附帶來源引用，使用者可驗證 |

### 7.2 資料隱私與安全

- **個資法遵循**：不蒐集個人健康資料，對話紀錄去識別化處理
- **資料儲存**：對話紀錄加密儲存，定期清除
- **第三方存取**：LLM API 調用不傳送個人識別資訊
- **使用者同意**：首次使用時顯示服務說明與免責聲明

> [!danger] 「不蒐集個人健康資料」與系統設計自相矛盾
> 這是一個衛教問答機器人 —— 病患描述自己的症狀**就是**個人健康資料。
> 「LLM API 調用不傳送個人識別資訊」在 v1.0 的實作裡也不成立（prompt 注入了 age 與 diagnosis）。

### 7.3 限制與風險管理

| 風險 | 可能影響 | 緩解策略 |
|---|---|---|
| LLM 幻覺 | 提供錯誤衛教資訊 | 嚴格限制僅基於檢索結果生成，無文件支持則明確告知 |
| 過度依賴 | 患者取代專業醫療 | 持續提醒「請諮詢醫療團隊」 |
| 知識庫過時 | 衛教內容不符最新指引 | 定期更新機制（每季度審查） |
| 文化敏感性 | 不符台灣本土醫療情境 | 納入台灣本土文獻與臨床指引 |
| 技術故障 | 系統無法回應 | 提供備援聯絡方式（護理站電話） |
