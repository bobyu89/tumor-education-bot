# Review 問題清單

> [!info] 範圍
> 審查對象為三份系統架構書、`.env`、`index_report.json`、`make_doc*.js`。
> **實作程式碼（`backend/`、`scripts/`、`frontend/`）不在此資料夾內**，
> 因此以下關於後端邏輯的判斷是根據架構書自己寫的規格與虛擬碼，不是讀真實實作。

## 🔴 P0 — 必須馬上處理

### 1. API Key 外洩

- [ ] **撤銷金鑰**

`.env` 的 `GOOGLE_API_KEY` 是一把真實可用的金鑰。`.gitignore` 有正確排除 `.env`，
但這個資料夾（`腫瘤衛教機器人-20260716T050020Z-1-001`）的命名是 Google Drive 的下載格式 ——
代表 `.env` **已隨資料夾上傳到雲端硬碟又下載回來**。`.gitignore` 只擋 git，不擋 Drive。

**處理**：至 [Google AI Studio](https://aistudio.google.com/apikey) 刪除該金鑰 → 建立新金鑰 →
更新本機 `.env` → 檢查 Drive 分享設定與 API 用量紀錄。
日後交付資料夾前，`.env` 與 `chroma_db/` 都要先移除。

### 2. 緊急警示會延遲 25–35 秒才通知護理師

[[v1.0 系統架構書#2.1 資料流程]] 的 Step 2 就完成了緊急偵測，但 Step 6 才廣播。
[[v2.0 LINE整合版架構書#5.3 核心邏輯重構（抽成共用函式）]] 的 `process_chat()` 同樣把
`broadcast_alert()` 放在 Gemma 呼叫**之後**。

```python
alert = detect_emergency(message)      # ← 第 1 行就知道是紅旗
rag_docs = retriever.query(message)
# ... Gemma 呼叫，25-35 秒 ...
if alert.is_emergency:
    await manager.broadcast_alert({...})   # ← 才在這裡通知
```

表達自傷意念的病患，護理師 25–35 秒後才收到通知，病患自己也要等同樣時間才看到「請按呼叫鈴」。

**處理**：偵測到 HIGH 立刻廣播 + 立刻回覆固定安全文字，**完全不進 RAG / LLM**。
緊急情況要的是確定性回應，不是生成。回覆內容可直接取用
[[(草案) 肺癌版 RAG 設計書#3.4.2 安全護欄機制]] 那張表（它比現行版完整，含 >38.5°C 閾值與安心專線）。

### 3. LINE Webhook 的寫法會直接 crash

見 [[v2.0 LINE整合版架構書#⛔ 第五章的三個致命問題]]。三個獨立問題：
`asyncio.run()` 在事件迴圈內呼叫拋 RuntimeError；同步阻塞事件迴圈 25–35 秒；
webhook 逾時導致 LINE 重送 + reply token 過期。

**處理**：webhook 立刻回 200 → 背景任務 → 用 Push API 回覆。

### 4. 隱私聲明講反了

[[v1.0 系統架構書#6.3 資料隱私]] 寫「Google API 僅傳送對話內容，無識別個人資料」。兩個問題：

1. Prompt 注入了 `age: 58`、`diagnosis: ["口腔癌","化學治療中"]` —— 這就是可識別的健康資訊。
2. 「一位 58 歲口腔癌病患描述自己的化療症狀」這段對話**本身**就是個人健康資料。

更關鍵：`.env` 用的是 **Google AI Studio 免費方案**，其條款明訂免費層送出的內容會被
Google 用於改善產品與訓練模型，並可能經人工審閱。付費 API 才有例外。

**處理**：確認最新條款 → 改用付費方案或全本地模型。這會影響技術選型，**應最優先與指導教授確認**。

三份文件中只有 [[(草案) 肺癌版 RAG 設計書#6.3 研究設計建議（若需學術發表）]] 提到 IRB，
現行版完全沒有 IRB / 知情同意 / 去識別化章節。

## 🟡 P1 — 該修但不擋路

### 5. 索引分類有 46% 是錯的

- [x] **已於 Markdown 化時修正** — 13 份 `category` 全部改為「腫瘤」

`index_report.json` 的 13 份有 6 份分類錯誤：

| 檔案 | 舊分類 | 正確 | 推測誤判原因 |
|---|---|---|---|
| [[ONC-19 紅血球減少]] | 呼吸 | 腫瘤 | 內文提到「喘、呼吸急促」 |
| [[ONC-22 腹瀉]] | 泌尿 | 腫瘤 | 內文提到「脫水、小便」 |
| [[ONC-35 穴位按摩]] | 心臟 | 腫瘤 | 內關穴屬心包經 |
| [[ONC-37 疲憊]] | 心臟 | 腫瘤 | 內文提到「心悸、心跳」 |
| [[ONC-39 過敏症狀]] | 呼吸 | 腫瘤 | 內文提到「呼吸困難」 |
| [[ONC-40 紅疹]] | 泌尿 | 腫瘤 | — |

根本原因：`scripts/utils.py` 拿器官系統關鍵字掃全文，但化療副作用單張本來就會提到各種器官系統。
這 13 份全是 ONC- 開頭的化療衛教單張，**定義上全部是「腫瘤」**，根本不需要推斷。

影響取決於 `category` 有沒有當 ChromaDB metadata filter —— 架構書沒寫清楚。
若有，病患問腹瀉時系統過濾 `category=腫瘤` 就永遠檢索不到 ONC-22。

### 5b. 舊向量庫有 77% 的 chunk 被汙染 ⭐ 實測

- [x] **已於重新索引時解決**

直接查詢 `chroma_db/chroma.sqlite3` 的 108 個 document，實測結果：

| 汙染類型 | Chunk 數 |
|---|---:|
| 含護理指導評值考題 | 29 |
| 含 DOI / 英文文獻網址 | 34 |
| 含頁首頁尾樣板（三軍總醫院／諮詢電話／審議會） | 43 |
| **至少被汙染一項** | **84 / 108（77%）** |

原因：舊版 `indexer.py` 直接把整份 PDF 的文字流以固定 400 字元硬切，
不區分衛教內文、參考文獻、評值考題與頁面樣板。

實際範例（這是一個可被檢索到的完整 chunk）：

```
(1)午睡勿超過30 分鐘；(2)避免喝酒或喝含咖啡因等刺激性飲料；
(3)入睡前如廁排空膀胱；(4)以上皆是。
（答對5-6 題➱完全了解；答對3-4 題➱部分了解；答對1-2 題➱完全不了解）
1.（X） 2.（O） 3.（O） 4.（4） 5.（4） 6.（4）
```

病患問「化療後睡不好怎麼辦」，檢索到這塊的話，模型拿到的「衛教資料」是一份考卷解答。

**處理**：新的 `scripts/index_vault.py` 改從 Markdown 建庫，依 `##` 章節邊界切割，
並排除 `## 參考資料` 與 `## 護理指導評值`。結果 72 chunks，實測 0 個含 DOI、0 個含考題、0 個含樣板。

### 6. 「緊急時模型升級」是空的

[[v1.0 系統架構書#4.3 緊急關鍵字偵測（backend/alert.py）]] 說 HIGH 觸發「模型升級（次級）」，
但 `.env` 裡 `PRIMARY_MODEL` 與 `SECONDARY_MODEL` 都是 `gemma-3-12b-it`。

**處理**：若採納問題 2 的建議（緊急不進 LLM），這個設計整個可以拿掉。

### 7. 認證薄弱

猜到 `R001` 就能讀 `/history/{任意病患}` 與 `/sessions` 的全部內容。
LINE 版更寬：任何人輸入 `P001` 就能綁定成該病患。

架構書把「使用者認證」列為「高」優先度**待辦** —— 但在接觸真實病患資料前，這是 **blocker**。

### 8. Session 存記憶體與研究用途矛盾

[[v1.0 系統架構書#6.3 資料隱私]] 把「重啟後清空」寫成隱私優點，
但這系統的存在目的就是讓研究者分析病患對話，且 IRB 通常要求研究資料留存數年。

**處理**：持久化 + 加密 + 存取控制 + 明確保存期限，而不是靠「反正會消失」當隱私保護。

### 9. 肺癌設計書全文字元損毀

見 [[(草案) 肺癌版 RAG 設計書]] 開頭的損毀對照表。噁→噤、嘔→嘆、疼/疲→疒 等，
**100% 損毀（沒有一個正確）**。Markdown 版已修復並標記存疑處。

### ⚠️ 對 RAG 有實質影響的

> [!warning] [[ONC-35 穴位按摩]] 的穴位定位依賴圖片
> 原文「往手臂的方向取 3 指幅，在此位置的中間點（如圖 B 打○處）」——
> 「中間點」必須對照圖 B 的○標示才能確定，PDF 沒有可獨立操作的文字定位敘述。
>
> **後果**：病患問「內關穴在哪裡」，機器人拿到的 chunk 本身就講不清楚，只能給出模糊或錯誤的定位。
> 這份的 frontmatter 已標 `needs_image: true`。
>
> **建議**：補一段純文字定位（例如「手腕橫紋正中往手肘方向約三指幅寬、兩條筋之間」），
> 或讓機器人在回答此題時改為推送圖片／建議詢問護理師。

> [!warning] [[ONC-39 過敏症狀]] 內文含緊急關鍵字
> 這份衛教單張本身就寫著「呼吸困難」「胸部疼痛」「心跳加速」。
> 若病患複述單張內容提問（「單張說呼吸困難要注意，那是什麼意思？」），
> 純關鍵字比對的 `alert.py` 會誤觸發 HIGH 紅旗警報。
> 這份的 frontmatter 已標 `contains_emergency_terms: true`。
>
> 這也暴露 `alert.py` 的通用弱點：沒有否定與語境處理。
> 「我**沒有**胸痛」「醫師說**如果**胸痛要回診」都會誤觸發；
> 反過來「我不想活了」「撐不下去」可能漏掉。
