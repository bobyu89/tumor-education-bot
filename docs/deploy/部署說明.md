# 部署說明（Docker）

> 適用：AWS EC2 等雲端主機，或醫院內的 Linux 主機。兩者步驟相同，差別只在網路與網域設定。
> **系統目前仍不可用於真實病患**：紅旗詞庫需先經臨床審核與獨立測試集驗證（見 PR #1 與審查報告）。

## 1. 架構

```
LINE 使用者 ──HTTPS──▶ Caddy（443，自動申請憑證）──▶ app（FastAPI，僅綁本機 8000）
護理端瀏覽器 ──HTTPS／WSS──┘                              │
                                                          ├─ volume app_data   SQLite（病患資料）
                                                          ├─ volume chroma_db  向量索引
                                                          ├─ volume models     嵌入模型
                                                          └─ 對外：Anthropic API、LINE API、首次啟動下載嵌入模型
```

- 映像**不含**病患資料、密鑰或模型權重；這些都在 volume 或 `.env`。
- app 只開**一個 worker**：護理端即時連線清單與 LINE 事件去重都在同一個行程內，不可開多個 worker 或多台橫向擴充。
- app 的 8000 埠只綁在主機的 127.0.0.1，對外一律經過 Caddy 的 HTTPS。

## 2. 主機需求

| 項目 | 建議 |
|---|---|
| 作業系統 | Linux（x86_64 或 arm64），已安裝 Docker 與 Docker Compose |
| 規格 | 2 vCPU、4 GB RAM、20 GB 磁碟（映像約 0.9 GB、嵌入模型約 0.5 GB） |
| 網域 | 一個指向這台主機的網域，例如 `bot.example.org`（LINE webhook 必須是 HTTPS） |
| 防火牆 | 對外只開 80、443（以及管理用的 SSH）；不要對外開 8000 |
| 對外連線 | `api.anthropic.com`、`api.line.me`；首次啟動需連 `huggingface.co` 下載嵌入模型 |

## 3. 第一次部署

```bash
git clone https://github.com/bobyu89/tumor-education-bot.git
cd tumor-education-bot
cp .env.example .env        # 依下表填寫，.env 絕不進版控
docker compose --profile https up -d --build
docker compose logs -f app  # 首次啟動會下載嵌入模型並建立索引，約需數分鐘；之後每次啟動自動同步
```

看到 `Uvicorn running` 後，用 `curl -s http://127.0.0.1:8000/health` 確認 `rag_chunks` 為 134。

### `.env` 必填與建議設定

| 變數 | 說明 |
|---|---|
| `AUTH_SECRET` | **必填**，未設定容器會拒絕啟動。產生方式：`openssl rand -hex 32` |
| `ADMIN_ACCOUNT`／`ADMIN_PASSWORD` | 首次啟動建立管理者帳號；建立後可把 `ADMIN_PASSWORD` 清空 |
| `DEMO_SEED` | **正式環境不要設定**（設 true 會建立示範帳號） |
| `LLM_PROVIDER` | 正式收案設 `anthropic` |
| `PRIMARY_MODEL` | `claude-sonnet-5-5` 或 `claude-opus-5-5` |
| `ANTHROPIC_API_KEY` | Anthropic API 金鑰 |
| `LLM_EFFORT` | 預設 `low` |
| `ANTHROPIC_REFUSAL_FALLBACK` | 預設 true；IRB 要求只能用單一模型時設 false |
| `LINE_CHANNEL_SECRET`／`LINE_CHANNEL_ACCESS_TOKEN` | LINE Developers Console 取得；兩者都有值才啟用 webhook |
| `EMERGENCY_CONTACT` | 病患看到的緊急聯絡指引，**請與醫院確認號碼是否 24 小時有人接聽** |
| `ALERT_SLA_HIGH_MIN` 等 | 警示確認時限，依值班 SOP 決定（見 `docs/ops/警示處理SOP_草案.md`） |
| `DOMAIN` | Caddy 申請憑證用的網域 |

### LINE 設定

LINE Developers Console → Messaging API → Webhook URL 填 `https://<DOMAIN>/line/webhook`，開啟「Use webhook」，按「Verify」應顯示成功。

## 4. 日常維運

**備份 SQLite（病患資料）**：建議每日一次，並把備份檔加密後存到另一個位置。保存期限依 IRB 核准的計畫書。

```bash
docker compose exec -T app python -c "import sqlite3,datetime; \
src=sqlite3.connect('/app/data/tumor_bot.sqlite3'); \
dst=sqlite3.connect(f'/app/data/backup-{datetime.date.today()}.sqlite3'); src.backup(dst)"
docker compose cp app:/app/data/backup-$(date +%F).sqlite3 ./backups/
```

**更新程式**：`git pull && docker compose --profile https up -d --build`（volume 內的資料不受影響）。

**更新衛教單張**：新增、改版（修改 frontmatter 的 `doc_version`）或停用（`rag_index: false`）後，重新部署即可：

```bash
docker compose --profile https up -d --build
```

容器每次啟動都會自動同步向量索引：刪除舊版與停用單張的段落、只計算有變動的單張；每則回答都會記錄當時依據的單張版本。
只有更換嵌入模型時才需要手動重建：`docker compose exec app python -X utf8 scripts/index_vault.py --rebuild`。

**查看紀錄**：`docker compose logs app`。紀錄可能含病患代號與錯誤訊息，主機存取權限要控管。

## 5. 特殊網路環境

**建置時經過會重新簽發 TLS 的代理**（醫院網路常見，`pip install` 出現 certificate verify failed）：把代理的 CA 憑證以 build secret 提供，不會寫進映像：

```bash
docker build --secret id=ca_bundle,src=/path/to/proxy-ca.crt -t tumor-education-bot:latest .
```

**沒有公開網域**（例如只在院內網路）：可先不加 `--profile https`，只用院內網址存取網頁；但 LINE webhook 需要 LINE 伺服器能連到的 HTTPS 網址，需與院方資訊室討論 DMZ 或反向代理。
