# Phase 2 設計書 — ESAS-r 症狀結構化追問

**日期**：2026-07-17
**狀態**：實作中
**前置**：Phase 1（持久化、紅旗、品質閘、認證）已完成

---

## 目標

病患**回報症狀**時，機器人先做一段簡短的結構化評估（了解目前狀況），再依嚴重度決定：
- 嚴重 → 升級為紅旗，通知護理師；
- 可自我照護 → 給對應的 RAG 衛教。

分級用 **ESAS-r 0–10**（Edmonton Symptom Assessment System-revised），每症狀再加 0–1 個症狀特有欄位。
所有分數落 `symptom_scores`（Phase 1 已建表），供第三期趨勢圖與研究匯出。

## 與紅旗的關係（雙層，Phase 1 已定）

```
病患訊息
 → ① 紅旗瞬間篩檢（Phase 1）      HIGH → 立刻推播+固定回覆
 → ② 症狀評估（本期）：
      有進行中的評估 → 處理回覆、推進狀態
      偵測到新症狀   → 開始評估（先問嚴重度）
      評估完成       → 分數落庫 → 嚴重則升級紅旗，否則 RAG 衛教
 → ③ 皆非 → 一般 RAG 問答（Phase 1）
```

紅旗永遠在最前（安全底線）。評估**不會延後急症**：胸痛等在 ① 就短路，根本進不到評估。

## 症狀清單（對齊知識庫）

每症狀綁一個 ONC 衛教主題與升級規則。ESAS-r 標準 9 症狀中，與化療衛教重疊者優先。

| 症狀 key | 顯示名 | 觸發關鍵字（例） | 衛教 ONC | 特有欄位 | 升級門檻 |
|---|---|---|---|---|---|
| pain | 疼痛 | 痛、疼 | — | 部位 | ESAS ≥ 7 |
| fatigue | 疲憊 | 累、疲憊、沒力氣 | ONC-37 | — | ESAS ≥ 7 |
| nausea | 噁心嘔吐 | 想吐、噁心、嘔吐 | ONC-21 | 一天吐幾次 | ESAS ≥ 7 或 吐≥5次/日 |
| appetite | 食慾不振 | 吃不下、沒胃口 | ONC-21 | — | ESAS ≥ 7 |
| diarrhea | 腹瀉 | 拉肚子、腹瀉 | ONC-22 | 一天幾次 | ESAS ≥ 7 或 ≥6次/日 |
| constipation | 便祕 | 便祕、大不出來 | ONC-23 | 幾天沒解 | ESAS ≥ 7 或 ≥3天 |
| mucositis | 口腔黏膜炎 | 嘴巴破、口腔潰瘍 | ONC-17 | — | ESAS ≥ 7 |
| neuropathy | 周邊神經病變 | 手麻、腳麻、刺痛 | ONC-38 | — | ESAS ≥ 7 |
| rash | 皮膚紅疹 | 紅疹、起疹子、皮膚癢 | ONC-40 | — | ESAS ≥ 7 |
| hair_loss | 落髮 | 掉髮、落髮、頭髮掉 | ONC-24 | — | 不升級（心理支持） |

注意：發燒、大量出血、呼吸困難、自傷等已在 Phase 1 紅旗攔截，不列入評估症狀。

## 狀態機

每位病患同時只有一個進行中的評估，存 `assessment_state`（可持久化、可重啟後續作）。

```
步驟：detect → ask_severity → [ask_field] → complete
```

- **detect**：訊息含症狀關鍵字且非紅旗 → 建立 state，回「聽起來您有[X]的困擾，方便先讓我了解一下嗎？這個不舒服 0（完全不會）到 10（最嚴重）分，您會給幾分？」
- **ask_severity**：解析 0–10（數字，或「輕微/還好」→2、「很/非常/受不了」→8 等詞對應）。有特有欄位 → 問欄位；否則直接 complete。
- **ask_field**：解析欄位（如「一天幾次」抓數字）。
- **complete**：
  1. 寫 `symptom_scores`（esas_symptom, score, extra json, source='patient_initiated'）。
  2. 判斷升級門檻：
     - 達門檻 → 建 `alerts`(level=medium) + WebSocket 推播 + 回「您的[X]情況比較嚴重，我已經通知護理師…」。
     - 未達 → 取該症狀 ONC 主題的 RAG 內容，走一般衛教回覆。
  3. 清除 state。

**中離**：病患在評估中途問別的、或說「先不用」→ 放棄評估（clear state），轉一般問答。用簡單規則：回覆中若無可解析的分數且含「不用/算了/先不」→ 放棄。

## LLM 的角色（混合，可選）

- **問題措辭**：預設用溫暖的模板句（不需 API key、可測試）。之後可讓 LLM 潤飾。
- **欄位抽取**：預設用規則解析（數字、程度詞）。之後 LLM 可從自由文字抽更準（「拉到虛脫、一天七八次」→ 次數=7）。
- 本期以模板 + 規則為底，確保無金鑰也能運作與測試；LLM 潤飾/抽取列為 enhancement，不阻擋第一版。

## 資料表

沿用 Phase 1 已建的 `symptom_scores`，新增一張輕量狀態表：

```
assessment_state(
  patient_code TEXT PRIMARY KEY,   -- 一人同時一個評估
  symptom      TEXT,
  step         TEXT,               -- ask_severity | ask_field
  data         TEXT,               -- json：已收集的欄位
  updated_at   TEXT
)
```

## 錯誤處理

- 解析不出分數 → 重問一次（「方便用 0 到 10 的數字告訴我嗎？」）；再失敗則放棄評估、轉一般問答，不卡住病患。
- 升級推播與落庫失敗不可互相阻擋（同 Phase 1 原則）。

## 測試

- 偵測 → 問嚴重度 → 給分 → （有欄位則問欄位）→ 完成。
- 嚴重度 ≥ 7 → 產生 alert（升級）。
- 嚴重度低 → 走衛教、不升級。
- 狀態持久化：評估中途「重啟」後仍能接續。
- 中離：評估中說「先不用」→ 放棄、轉一般問答。
- 全部不需 API key。

## 非目標（留待第三期）

- 症狀趨勢圖、CSV 匯出、主動定時回報、知識測驗前後測、Telegram 通知。
- LLM 潤飾問句與自由文字欄位抽取（本期用模板 + 規則）。
