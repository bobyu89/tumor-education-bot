# 演示腳本（模擬案例）

給口試、課堂或團隊展示用。所有病患皆為虛構（姓名標「模擬」），資料只在本機 SQLite。
整份腳本 **不需要任何 API key** 也能跑（演示模式），有 key 時同一套情境可切成真實 LLM。

> 沒時間裝環境？直接開線上靜態版：<https://bobyu89.github.io/tumor-education-bot/>
> 同樣的情境 S1–S7 與測驗都能點，右側就是護理站儀表板（純前端模擬，無後端）。

## 0. 三分鐘準備

```bash
# 專案根目錄
cp .env.example .env                              # 預設 LLM_PROVIDER=mock（演示模式）
cd backend && pip install -r requirements.txt && cd ..
python -X utf8 scripts/index_vault.py --rebuild   # 建向量庫（首次會下載嵌入模型）
python -X utf8 scripts/seed_demo.py --reset       # 植入 5 位模擬病患與兩週歷程
python -X utf8 scripts/demo_dry_run.py            # 彩排：9 個情境全自動跑一遍，應顯示「通過 24 / 24」
cd backend && python -X utf8 -m uvicorn main:app --port 8000
```

瀏覽器開 <http://localhost:8000>。建議開兩個視窗：左邊登入研究者 **R001**（看警示與統計），右邊登入病患。

| 帳號 | 密碼 | 角色 | 設定給演示看的重點 |
|---|---|---|---|
| P001 | patient123 | 陳先生（模擬）58 歲 口腔癌 | 一般語氣；口腔黏膜炎；測驗 3→5 分 |
| P002 | patient123 | 王女士（模擬）72 歲 大腸癌 | **長者語氣（simple）**；腹瀉 5→3→2 分逐日改善；手麻 |
| P003 | patient123 | 林小姐（模擬）45 歲 乳癌 | 落髮 8 分但**不升級**（心理支持）；噁心嘔吐 8 分/6 次 → **升級警示** |
| P004 | patient123 | 張先生（模擬）63 歲 肺癌 | **詳細語氣（detailed）**；發高燒 medium；胸痛 → **HIGH 紅旗** |
| P005 | patient123 | 黃先生（模擬）35 歲 淋巴瘤 | 知識庫外問題 → 轉介；「撐不下去」→ **HIGH 自傷紅旗**；疲憊 |
| R001 | research123 | 研究者 | 儀表板、症狀統計、CSV 匯出 |
| A001 | admin123 | 管理者 | 同研究者權限 |

### 演示模式 vs. 真實 LLM

| | `LLM_PROVIDER=mock`（預設） | `google` / `anthropic` |
|---|---|---|
| 需要 API key | 否 | 是 |
| 紅旗、症狀評估、RAG 檢索、品質閘、落庫 | 完全相同 | 完全相同 |
| 「生成」這一步 | 本地規則把檢索段落整理成條列，回覆末尾標「演示模式」 | 真實模型依病患年齡／教育程度改寫 |
| 適合 | 展示流程與安全機制、無網路、CI | 展示個人化語氣、多輪對話 |

要切真實模型，只改 `.env`：`LLM_PROVIDER=google` + `GOOGLE_API_KEY=...`，程式不動。
現場若模型逾時或額度用完，系統會回固定降級文字並標記 `llm_error`，不會當機；情境 3–6 完全不經 LLM，不受影響。

## 1. 情境（依建議演示順序）

每個情境給「輸入原文」與「應該看到什麼」。輸入請照打，關鍵字與門檻是設計好的。

### S1 一般衛教問答 — 有憑有據

登入 **P001**，輸入：

> 化療後掉頭髮會長回來嗎

看到：回覆下方列出來源 **ONC-24 毛髮脫落**；演示模式下每一點都出自該單張。
講解：RAG 先檢索 13 份衛教單張，模型只能用檢索到的內容回答，來源可追溯。

### S2 症狀評估未達門檻 → 衛教

同一帳號，依序輸入：

> 我一直拉肚子
> 3分
> 一天四次

看到：機器人先問 0–10 分，再問次數，最後回「您的腹瀉嚴重度是 3/10」+ **ONC-22 腹瀉** 衛教。
講解：ESAS-r 結構化追問不需 LLM；分數落 `symptom_scores`，研究者端可看趨勢。腹瀉門檻是 **≥7 分或一天 ≥6 次**。

### S3 症狀評估達門檻 → 升級、通知護理師

> 打完針之後一直想吐
> 8
> 吐了六次

看到：「聽起來比較嚴重…已通知護理師」、畫面出現緊急橫幅；**左邊研究者視窗即時彈出警示**（SYMPTOM_ALERT，medium）。
講解：噁心嘔吐門檻 ≥7 分或 ≥5 次。升級走 WebSocket 推播，同時寫入 `alerts`。

### S4 HIGH 紅旗瞬間短路（最重要的一個）

> 我現在胸痛而且喘不過氣

看到：**不到一秒**回固定安全文字「請按呼叫鈴…已通知護理站」，來源為空；研究者視窗紅色 EMERGENCY_ALERT。
講解：HIGH 紅旗在進 RAG／LLM 之前就攔截，緊急情況要的是確定性回應，不是生成。

### S5 否定語境不誤觸

> 醫師說如果胸痛要回診，我現在沒有胸痛，平常要注意什麼

看到：**沒有**觸發緊急，正常回衛教。
講解：關鍵字前 8 字內有「沒有／如果／萬一」等詞就抑制，避免病患複述醫囑就被誤報。

### S6 自傷語意從寬觸發

> 最近每天都好累，覺得撐不下去了

看到：觸發 HIGH（關鍵字「撐不下去」），研究者端收到警示。
講解：自傷／心理類**不套否定規則**（「不想活」本身就含「不」），寧可誤報不可漏接。

### S7 知識庫外問題 → 誠實轉介，不編造

> 請問醫院的停車場在哪裡

看到：「這個問題我需要請護理師來幫您解答，我先幫您記錄下來」，`answer_quality` 標 `deflected_*`。
講解：品質閘：沒有可用來源就不進 LLM；模型自述無法回答也會被標記，研究者可稽核「回答品質分布」。

### S8 知識測驗前後測

病患畫面右上 📝 → 選「腹瀉」→ 作答提交（phase 可選 pre／post）。
看到：即時評分與逐題檢討；研究者「症狀統計」出現該主題 pre／post 平均分。
講解：題庫由 13 份單張的「護理指導評值」抽出，出題端點不含答案。

### S9 研究者儀表板與去識別化匯出

登入 **R001**：
1. 左側病患列表：P001–P005，紅旗數、最後一句。點 **P004** 看時間軸（發高燒 medium → 胸痛 high）。
2. 「症狀統計」：病患數、各症狀平均分／嚴重數、警示數、回答品質分布、測驗前後測。
3. 「CSV 匯出」：下載 `symptom_scores.csv`，打開看只有 **P001…** 假名，沒有真名。

講解：身分表與研究表分離，真名只存在 `patients`，匯出白名單裡沒有 `real_name`；病患 token 存取匯出會回 403。

### 加碼：長者語氣

登入 **P002**（72 歲，simple），問同一個問題「化療後掉頭髮會長回來嗎」，對照 P004（detailed）。
真實 LLM 模式下差異最明顯：P002 句短、有比喻、只講 1–2 個重點；演示模式下 P002 只引 1 段、2 個要點。

## 2. 常見狀況

| 狀況 | 處理 |
|---|---|
| `/health` 的 `rag_chunks` 是 0 | 沒建索引：`python -X utf8 scripts/index_vault.py --rebuild` |
| 研究者視窗沒彈警示 | 研究者頁要**先**開著（WebSocket 連上）再讓病患送訊息；重整後需重新登入 |
| 想清掉演示時打的對話 | `python -X utf8 scripts/seed_demo.py --reset` 回到初始資料 |
| 評估卡在「請用 0 到 10 的數字」 | 回「先不用」可中止評估 |
| 換成真實模型後回覆變慢 | 正常（Gemma 免費層 10–30 秒）；S3–S6 不受影響 |
| 對話被判為緊急但你覺得不該 | 關鍵字表在 `backend/redflag.py`，可調；設計取向是「寧可誤報」 |

## 3. 接到 LINE Bot 之後（規劃）

這套情境刻意設計成「純文字進、純文字出」，LINE 版只是換入口：

```
LINE 病患訊息 → POST /webhook（驗簽、立刻回 200）
              → 背景任務：查 userId↔病患代號 → 與 /chat 相同的處理鏈
              → Push API 回覆病患；HIGH 紅旗照樣先推播護理站
研究者儀表板不變。
```

已知必須處理的三件事（詳見 `Obsidian_Vault/系統文件/v2.0 LINE整合版架構書.md`）：

1. **webhook 不能同步等 LLM**：LINE 要求立即回 200，reply token 會過期 → 背景任務 + Push API。
2. **綁定不能只靠輸入 P001**：改一次性綁定碼，由護理師當面發給病患，用過即失效；對應表存 SQLite，不存記憶體。
3. **訊息長度**：LINE 單則 5000 字，回覆需截斷；可考慮把「來源」改成第二則訊息或 Flex Message 卡片。

演示情境 S1–S7 在 LINE 上的輸入文字與預期行為完全相同，`scripts/demo_dry_run.py` 屆時可直接改打 `/webhook`（用假簽章）當回歸測試。
金鑰 `LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN` 一律放 `.env`（`.env.example` 已預留欄位）。
