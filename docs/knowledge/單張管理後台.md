# 單張管理後台

管理者在網頁上**上傳、預覽、上架、停用、退回**衛教單張，不用碰程式或 GitHub。上架後立即生效：下一則病人提問就使用新版。

入口：以管理者帳號登入 → 右側「管理者專區」→ **📚 單張管理**。

## 原則

- **單張內容照院內核可版本**：系統只做格式轉換（Word、PDF → 純文字），不改寫。
- **只有管理者能上傳與上架**；每一次上傳、上架、停用、退回都記入人員稽核紀錄。
- **每一版都保留**（含原始上傳檔），可隨時退回任何一個曾上架的版本，或退回院內原始版。

## 上傳與上架

1. 在清單按某份單張的「上傳新版」，或上方「＋ 上傳單張」（新單張）。
2. 選檔案：**Word（.docx）**、**Markdown（.md）** 或 **PDF**，上限 10 MB。
3. 填「新版本」（例如 `2026.12 九版`，**必須與目前版本不同**）。標題、分類等欄位留空時沿用檔案或目前版本。
4. 按「轉換並預覽」，檢查：
   - **章節與段落數**：每個章節切成幾段進入知識庫；「參考資料」「護理指導評值」不會進入知識庫。
   - **看切好的段落**：病人提問時檢索的就是這些段落。
   - **紅色問題**（必須處理才能上架）：代碼格式不對、缺標題／分類／版本、版本與目前相同、沒有內容。
   - **橘色提醒**：新單張、沒有偵測到章節、與原檔文字不同、PDF 需逐段核對。
5. 需要時在內文框補上章節標題（`## 標題`）或修正斷行，按「更新預覽」。
   **不要改內容**：系統會比對原檔轉出的文字，改了任何字都會顯示「新增／刪除幾字」與差異示例。
6. 按「✅ 上架」。

### 各格式注意事項

| 格式 | 轉換方式 | 需要注意 |
|---|---|---|
| Word | 「標題」樣式 → 章節，項目清單 → 「- 」，表格每列一行 | 單張裡的章節請用 Word 的「標題」樣式，系統才分得出章節 |
| Markdown | 直接使用；frontmatter 的欄位會自動帶入 | 需為 UTF-8 |
| PDF | 抽出文字、去除每頁重複的頁首頁尾與頁碼、把句中斷行接回 | **必須逐段與原檔核對**並勾選「已逐段核對」才能上架；章節標題需自行補上；掃描圖檔 PDF 無法讀取 |

## 停用與退回

在清單按「版本」：

- **停用這份單張**：之後病人的提問不會再用到它（例如院內已廢止）。
- **退回到這一版**：回到任何一個曾上架的版本。
- **退回院內原始版**：刪除後台的改版，回到 repo 裡的原始單張。
- **原檔**：下載當時上傳的檔案核對。

## 運作方式（給維護人員）

- 上架中的單張寫在 `data/leaflets/<科別>/<代碼>.md`（覆蓋層）：同代碼時取代 `source_dir` 的原始單張；
  `rag_index: false` 表示停用。`scripts/index_vault.py` 啟動時也讀這裡，容器重啟後狀態不變。
- 版本紀錄在資料庫 `leaflet_versions`（schema v6）；原始上傳檔在 `data/leaflets/_files/`。
- 上架、停用、退回時在服務內直接同步向量索引（只重算有變動的單張），同步失敗會還原檔案。
- `data/` 在 Docker 的 `app_data` volume 上，**備份資料庫時一併備份 `data/leaflets/`**。
- 程式：`backend/leaflets.py`；API：`/admin/leaflets/*`；測試：`backend/test_leaflets.py`。

## 與 repo 裡的單張的關係

repo 的 `Obsidian_Vault/衛教知識庫/` 是院內原始版本，後台不會修改它。若希望某次後台改版也成為 repo 的正式版本，
由維護人員把該版的檔案（版本紀錄 → 原檔，或 `data/leaflets/<科別>/<代碼>.md`）提交到 repo，部署後再於後台「退回院內原始版」即可。
